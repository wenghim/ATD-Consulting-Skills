# DOCX Format Profile Schema 1.0

Use this contract for JSON files generated by `scripts/analyze_docx_format.py` and consumed by the catalog and profile applier.

## Top-level fields

| Field | Type | Meaning |
|---|---|---|
| `schema_version` | string | Must be `1.0`. |
| `analyzer_version` | string | Analyzer implementation version. |
| `identity` | object | Variant and source identity. |
| `sections` | array | Page geometry and section settings. |
| `theme` | object | Major/minor fonts and color scheme. |
| `styles` | object | Resolved paragraph and character styles keyed by style ID. |
| `semantic_roles` | object | Reusable formatting keyed by normalized role. |
| `paragraphs` | array | Paragraph-level style, role, and layout observations. |
| `direct_formatting_exceptions` | array | Run or paragraph overrides that differ from the base style. |
| `numbering` | object | Numbering definitions referenced by the document. |
| `tables` | array | Table geometry, styles, borders, fills, and cell observations. |
| `images` | array | Image part and placement metadata. |
| `headers_footers` | object | Header and footer content and style observations. |
| `limitations` | array | Unsupported, ambiguous, or unresolved features. |

## Identity

Required fields:

```json
{
  "variant_id": "corporate-blue",
  "variant_name": "Corporate Blue",
  "source_filename": "reference.docx",
  "source_sha256": "hex digest",
  "analyzed_at": "ISO-8601 UTC timestamp"
}
```

Derive `variant_id` from a sanitized explicit variant name. Do not derive identity from document text.

## Formatting values

Use points for type and paragraph spacing, inches for page geometry, DXA for Word table widths when present, and uppercase six-character RGB strings for explicit colors.

A reusable font block may contain:

```json
{
  "name": "Aptos",
  "size_pt": 11.0,
  "bold": false,
  "italic": false,
  "underline": false,
  "color": "1F4E79",
  "theme_font": "minorHAnsi",
  "theme_color": "accent1"
}
```

Use `null` when a property cannot be resolved. Do not replace unknown values with defaults unless the default is explicitly present in the OOXML inheritance chain.

## Semantic roles

Normalize reusable roles to:

`normal`, `title`, `subtitle`, `heading_1`, `heading_2`, `heading_3`, `quote`, `caption`, `list_bullet`, `list_number`, `header`, and `footer`.

Each role must include its source style ID, confidence, evidence, font, and paragraph formatting. Explicit Word style names receive higher confidence than heuristics. Flag values below `0.70` for human review.

## Images

Record the package part, relationship ID, media type, byte size, intrinsic or drawing dimensions when available, inline or anchored placement, containing paragraph and section, title/description or alt text, and nearby caption evidence. Do not extract or copy image binaries unless the user requests it.

## Catalog compatibility

The catalog consumes only identity, profile paths, a short style summary, and timestamps. A catalog entry points to the full profile; it does not duplicate the full analysis.
